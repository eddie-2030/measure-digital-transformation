# Data dictionary

All files are synthetic (see README). Generated by `generate_data.py` with seed 20261104.

## ai_supervision_assessment.csv (612 rows, one per test record)

| Column | Type | Meaning | Units / values |
|---|---|---|---|
| person_id | string | Test-taker ID | P0001–P0612 |
| business_unit | string | Business unit. 9 labels are typed inconsistently (case, trailing space); the analysis fixes them | Trust & Safety Review, Operations, Claims, Customer Support |
| role | string | Job role (descriptive only, not used in the analysis) | e.g., Content reviewer, Claims examiner, Team lead |
| completion_minutes | float | Time spent on the assessment. Under 8 minutes = speeder rule | minutes |
| S01–S12 | integer (blank = missing) | Scenario-based performance items: the test taker reviews an AI output and must spot the error, decide whether to escalate, or verify a claim against a source. Partial-credit score | 0–4 points |
| C01–C04 | integer (blank = missing) | Self-report confidence items with near-duplicate wording (e.g., "I feel comfortable checking AI output", "I can tell when an AI answer is wrong") | 0 (not at all confident) to 10 (completely confident) |
| audit_seeded_a, audit_seeded_b | integer (blank = no audit) | Number of seeded errors in each of two parallel sets of AI outputs in the work-sample audit, about 3 weeks after the test | errors (19–21 per set) |
| audit_caught_a, audit_caught_b | integer (blank = no audit) | Seeded errors the person caught in each set | errors |

Derived in the analysis (not in the file):

| Name | Meaning |
|---|---|
| audit_pct_caught | Criterion: (caught_a + caught_b) / (seeded_a + seeded_b), share of seeded errors caught |
| audit_a, audit_b | Share caught in each half; their correlation (Spearman-Brown corrected) gives the criterion's reliability |
| score_naive16 | Prorated sum of all 16 items (mixes 0–4 and 0–10 items, as a naive total would) |
| score_scenario12 | Prorated sum of S01–S12 (0–48) |
| score_scenario10 | Prorated sum of the 10 kept scenario items (0–40); certification cutoff = 26 |
| score_conf4 | Prorated sum of C01–C04 (0–40) |

Missing-data rule: a scale score is the mean of the answered items × the number of items, if at least 75% of the scale's items were answered (8 of 10, 9 of 12, 12 of 16, 3 of 4); otherwise missing. Reliability and item statistics use pairwise-complete covariances.

Speeder rule: exclude a record if `completion_minutes < 8` OR the person gave the same answer to every answered scenario item (with at least 9 answered).

## true_parameters.csv (ground truth; used only in Step 3)

| Column | Meaning |
|---|---|
| parameter | Name: generating loadings (`loading_S01` …), the skill-confidence correlation, the audit model, the flawed items, and population values `true_reliability_*`, `true_validity_*` computed on 1.5 million simulated people |
| value | Number (or text for `flawed_items`) |
| meaning | One-line explanation |

## true_person_values.csv (ground truth; used only in Step 3)

| Column | Meaning |
|---|---|
| person_id | Matches the assessment file |
| is_speeder | 1 = generated as a speeder (no true values) |
| theta | True AI supervision skill (latent, mean about 0, SD about 1) |
| confidence_factor | True AI confidence (latent) |
| true_catch_rate | The person's true probability of catching a seeded error |
| true_score_scenario10 | Expected score on the 10 kept scenario items given theta (0–40): the "true score" used to check pass/fail classification |
| true_score_conf4 | Expected confidence score given the confidence factor (0–40) |
